Runner event stream

Goal

The runner reports what happens in a run as it happens, so no client polls for status.

Event stream at the runner

The runner serves one server-sent event stream on its loopback port, behind the same bearer token as its HTTP routes.

Event kinds

started, tool call, silent for N minutes, gate red, done, and quota: a slot's remaining share and reset time after every turn.

Clients read through the engine

The engine tails the runner's stream files and puts the events on its own /api/events. A client that reconnects reloads the board; there is no replay.

Out of scope

Events between two runners; a stream for a single persona; replaying missed events.
